# 方案决策

## 2026-10-28 08:48:21 +00:00 — 沿用原生部署并先提供手动发布

背景：用户要求将 CI/CD 接到 `ssh wdm` 的既有 Oak 实例，明确选择先手动触发，确认后再考虑自动发布。服务器资源有限，现有 systemd/Caddy/PostgreSQL/Redis 已运行。

备选：服务器自行编译或安装自托管 Runner；迁移到容器；在 GitHub 托管 Runner 构建静态程序后传输。选择第三种，复用原有运行方式，避免生产服务器承担构建负载或改变数据部署结构。

实现位于 `.github/workflows/oak-deploy.yml`、`deploy/oak/package-release.sh` 和 `deploy/oak/ci-deploy.sh`。只接受手动触发，默认仅构建；启用部署需专用受限 SSH 凭据，主机公钥固定验证。服务器处理器已安装，GitHub 空环境已创建；密钥及工作流推送尚未完成，不能认为发布链路已经启用。

代价：更新时短暂停止应用以备份。新版本启动会运行迁移，因此启动后失败只停止服务并保留备份，不能自动恢复旧二进制或数据库。实际停机发布与恢复演练尚未执行。

## 2026-10-28 09:09:22 +00:00 — 官方跟踪与定制发布分支分离

背景：用户要求保留纯官方跟踪分支，授权继续接入和提交推送，GitHub 私钥由用户录入。本条替代 2026-10-28 08:48:21 +00:00 条目中尚未落地的分支接入方式，不再向旧 main 挑选 CI 文件。

备选：将 main 变为定制分支并另建官方分支；或把定制和 CI 放到独立默认分支。选择 `upstream-main` 纯跟踪官方、`oak` 承载定制并设为 GitHub 默认分支，保留旧 main。GitHub 手动触发要求默认分支存在工作流，因此默认分支须随部署入口切到 oak。

代价：默认 PR 基准也变为 oak；后续官方更新先快进 upstream-main，再人工评估合入 oak，不自动将未经验证的新提交发布到生产。工作流和生产环境均显式限定 oak。分支推送与默认分支切换最终状态见交接记录。

## 2026-10-29 05:24:14 +00:00 — oak 推送后自动测试并发布

背景：手动发布已验证成功，用户要求将 oak 改为推送后自动触发并自动发布。本条替代 2026-10-28 08:48:21 +00:00 决策中“仅手动触发”的发布方式，保留 2026-10-28 09:09:22 +00:00 的分支隔离。

备选：仅自动构建后仍手动发布；或推送 oak 后在构建成功时自动发布。选择后者，新增限定 oak 的 push 事件，部署条件为推送事件或手动 deploy=true，继续通过 needs:build 保留测试和构建门禁。

代价：每次 oak 推送都可能更新生产，包括文档提交；推送前应完成审查。沿用串行部署、备份和健康检查，启动后失败不自动恢复旧二进制；不增加新的开关、密钥或服务器配置。

## 2026-10-30 09:55:17 +00:00 — 订阅再次付款续期，禁止余额兑换

背景：用户明确要求同套餐再次购买应延长时间，并在实施中明确禁止使用平台余额购买或续期；同时要求将 dev 分支微信支付迁到 oak。

备选：维持重复购买多实例、仅关闭余额按钮；或统一到账规则为同套餐续期并移除余额扣款路径。选择后者，所有网关共享 `model/subscription.go` 的订单事务；直接支付完成后延长有效期，不增加本期额度。官方微信/支付宝共用旧渠道框架，精确迁移必要实现，保留当前 oak 的额度上限、权限与其他网关。

代价：删除余额购订阅 API 与配置字段；历史列留存但不再决定行为。新增原微信 SDK 及冻结充值额度列；需要真实三库迁移验证和后续商户端联调。套餐的周规则与模型调用的钱包回退策略没有借机调整，存量并行订阅不自动合并。参考 `controller/subscription_payment_official.go`、`model/subscription_renewal_test.go`、`router/access_token_scope_test.go`。

## 2026-10-30 11:58:20 +00:00 — CNY 本地充值采用人民币面额输入

背景：用户报告选择人民币后输入 1 仍需支付 7.3，明确要求一元输入对应一元付款和一元到账，并要求面额/应付/到账公式；范围限定微信、支付宝、易支付。

备选：保留美元数量输入并只改标签；或统一人民币本地报价、入账冻结和展示。选择后者，CNY 不再乘美元售价 Price，汇率只换算内部额度，原分组/面额优惠仍保留。为避免只修界面，报价返回服务端 credited_quota，新易支付订单冻结该值，回调和人工补单共用。

代价：CNY 本地支付的输入含义改变；旧零冻结订单仍按旧美元合同兑现。国际支付渠道不改变计价。前后端须一起发布，旧后端若缺少到账报价字段，新前端会提示报价不可用并阻止确认。参考 controller/topup_currency_test.go、model/payment_method_guard_test.go、web/src/features/wallet/__tests__/currency-payment.test.tsx。

## 2026-10-31 20:16:00 +00:00 — 人工开票、分组附加费与独立财务权限

背景：用户要求充值选择是否开票、常用抬头/快捷配置、分组加价和财务管理，并确认人工上传文件及附加费不增平台额度。现有系统没有发票业务模型，已有支付快照和Casbin资源权限可复用。

备选：付款后仅登记文字、接税务服务商；或先完成手工开票文件交付。选择后者，新增私有抬头/申请表，订单与收费/资料同事务冻结，真实支付成功才进入财务队列。加价以默认百分比和组覆盖表达，0–100且最多四位小数，金额四舍五入到分；既有CNY报价/到账额度保持分离。

权限选择数字角色5并授finance读写，低于Admin10，避免旧AdminAuth等级比较顺带开放全部管理功能。Root创建/授予沿用原step-up，角色变更撤销旧会话和覆盖；API/PAT/UI共同限制。

代价：新增表、订单布尔字段和私有附件目录需随数据库备份；需前后端一起发布。仅CNY本地网关及本地订阅支持发票，其他渠道明确拒绝，不虚假收费。拒绝/已开具为当前终态，退款、红冲、重开和自动税务开票留待明确需求。参考 controller/invoice_test.go、service/authz/resources_finance.go 和 web/src/features/invoices/。
