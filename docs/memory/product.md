## 订阅续期与官方支付现状

2026-10-30 用户确认同套餐再次购买应延长有效期，且购买、续费均禁止使用平台余额。已在 `model/subscription.go` 统一支付完成和管理员开通的续期规则：活跃同套餐延长原到期时间，保留额度、已用量和重置时间；不同套餐、已过期或已取消按新开通，原历史限购规则保留。到期前已创建订单、到账时自然过期的续费可兑现。多个存量活跃同套餐不自动合并或删除，仅延长最晚到期的一份。

用户余额购订阅的模型/控制器函数、路由、权限声明、前端 API/按钮/套餐开关均已移除；历史数据库列不强制删除。管理员授权入口及模型调用的订阅/钱包计费偏好保留，后者与购买支付方式不同。并发付款统一按订单、用户、订阅顺序持锁，取消、删除及到期操作也先锁用户。

已把旧 dev 两笔官方支付改动（`504c53567`、`c2a94666d`）精确移入 oak，包括微信 Native/H5、公钥验签、官方支付宝共用框架、商户配置脱敏、充值二维码和本人账单继续支付；新增 `/api/subscription/official/pay` 让用户通过官方商户直接购买或续费，收款不经过钱包。共用通知按业务订单分流，并匹配商户/AppID、渠道及金额。仅新增原 SDK `wechatpay-go v0.2.21`，未整分支合并或降级依赖。

官方充值新增 `top_ups.credited_quota` 冻结下单额度。未完整冻结的官方订单拒绝入账，不按当前价格猜测。窗口到期只拒继续付款，成功通知可迟到；真实支付回调仍为唯一到账依据。配置路径、回调和复现命令见 [中文说明](../../README.zh_CN.md#oak-订阅续期与官方微信支付)。本轮尚未配置或迁移真实商户凭据，未真实付款或发布。

## 采购联系配置

配置入口、操作语义、上传限制与验证命令见 [中文说明](../../README.zh_CN.md#oak-官网与采购联系配置)。姓名、微信号、二维码与微信登录完全独立。上传与删除仅允许超级管理员，首页读取公开状态与图片接口；图片复用现有系统选项存储，无新增依赖或数据库结构。

徽标设置现改为与采购二维码共用上传控件 `web/src/features/system-settings/components/settings-image-field.tsx`，选图与删除即时保存，不再编辑 URL。后端共用 `controller/option_image.go` 的格式、大小及尺寸校验；徽标专用管理路径为 `/api/option/logo`，公开图片路径为 `/api/status/logo`，内部 `LogoImageData` 不进入配置列表。既有 `Logo` 继续作为公开展示地址，普通设置接口拒绝写入该字段及内部编码。没有新增表、迁移或依赖。

图片成功预览与普通设置草稿独立，避免上传后保存其他字段导致旧图重新出现；同一组件也用于采购图片。站点状态缓存失效后同步更新页头与 favicon。整页保存回归、采购上传回归及控制器、真实路由测试已验证。

验证依据：`controller/procurement_contact_test.go` 与前端首页、采购上传和校验测试。后端定向测试使用 SQLite；没有执行 MySQL/PostgreSQL 兼容矩阵，也未进行生产部署验证。
